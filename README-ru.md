# NeyziShop — обновлённая версия

Основной файл — `index.html`. В форме входа добавлен сброс пароля через письмо Firebase. На регистрации сайт теперь требует пароль от 8 символов; старые пароли по-прежнему можно вводить при входе.

## Настройка сброса пароля

В Firebase Console проверьте:

1. **Authentication → Sign-in method** — включён вход по email/паролю.
2. **Authentication → Templates** — настроен шаблон Password reset и отправитель писем.
3. **Authentication → Settings → Authorized domains** — добавлен домен, где размещён сайт.

После нажатия «Забыли пароль?» пользователь вводит email и получает ссылку; проверить стоит также папку «Спам».

## Базовая защита

- Включите Password policy в Firebase Authentication (минимум 8 символов) и Email enumeration protection.
- Ограничьте Firebase API key разрешёнными доменами в Google Cloud. Клиентский key не является секретом.
- Настройте Firebase App Check для веб-приложения: сначала Monitor, затем Enforce для Firestore.
- Не используйте открытые Firestore Security Rules.

**Важно:** UI-проверка роли — не защита базы. Сейчас браузерный код сам пишет баланс, покупки, промокоды, заказы и товары в Firestore. Если запретить эти записи правилами, соответствующие функции сайта перестанут работать. Для безопасной защиты перенесите покупку, возврат, активацию промокода и админские изменения баланса в доверенные Firebase Cloud Functions; выдавайте админские права через custom claims, а не через редактируемое поле профиля. После этого правилами запретите клиенту менять баланс и роль.

## Запуск

Размещайте сайт по HTTPS, не открывайте через `file://`. В Firebase должны быть включены Authentication и Firestore, а домен сайта добавлен в Authorized domains.
